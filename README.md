# エネルギー白書に質問できるAI（RAG × Claude）

資源エネルギー庁「エネルギー白書2026」のPDFを取り込み、日本語の質問に**白書の該当ページを引用して**答えるシステムです。
白書に書かれていないことは推測で答えず、「見つかりませんでした」と答えます。

> 「御社のマニュアル・規程・報告書PDFに差し替えれば、同じ仕組みが社内向けに使えます」という実例として作っています。

## 特徴

| | 内容 |
|---|---|
| 根拠を必ず示す | Claude API の引用機能（search_result ブロック）を使い、回答の各部分に出典ページと引用文を付ける。Web画面では、引用したページを画像で表示し、根拠の文に色を付ける |
| 答えられないときは答えない | 抜粋に答えがなければ「見つかりませんでした」と返す。数値は抜粋どおりに書き、計算や推測で作らない |
| 日本語に強い検索 | 文字2文字単位のキーワード検索（BM25）で固有名詞・番号の取りこぼしを防ぎ、任意でベクトル検索を加えて言い換えにも対応（RRFで統合） |
| 白書PDFに合わせた取り込み | 2段組みの読み順の判定、柱・ページ番号・余白タブの除去、行の途中で切れた文のつなぎ直し、全角数字の正規化、「第○部／章／節」の見出し階層と番号付き小見出しの判定、目次ページの除外。抜粋はページをまたがない |
| 精度を数字で示す | 質問セットから「検索の正解率」「引用の正確さ」「答えられない質問への正しい対応」を自動で測る |

## 仕組み

```
PDF ──取り込み──▶ 抜粋（ページ番号・見出し付き）──▶ 索引（キーワード ＋ 任意でベクトル）
                                                              │
質問 ──────────────────────────────▶ ハイブリッド検索 ─▶ 上位8件の抜粋
                                                              │
                                     Claude（search_result として渡す）
                                                              │
                                     回答 ＋ 引用（ページ・引用文）
```

| ファイル | 役割 |
|---|---|
| `rag/ingest.py` | PDF → ページ → 抜粋（チャンク） |
| `rag/search.py` | BM25（文字bigram）、ベクトル検索、RRF による統合 |
| `rag/embed.py` | 埋め込み（なし / Voyage AI / 手元で動く multilingual-e5） |
| `rag/answer.py` | Claude への依頼文の組み立て、引用の整理 |
| `rag/pdfview.py` | 引用ページの画像化と引用箇所の色付け |
| `build_index.py` | 索引を作る |
| `ask.py` | コマンドラインで質問する |
| `app.py` | Web画面（Streamlit） |
| `eval/evaluate.py` | 精度の評価 |
| `tests/` | APIキーなしで動く通しのテスト |

## 準備（Windows ＋ VS Code）

1. このフォルダを VS Code で開き、`Ctrl+Shift+P` →「Python: 環境の作成」→「Venv」→ `requirements.txt` にチェック
2. **白書のPDFを入れる**：[エネルギー白書2026 PDF版](https://www.enecho.meti.go.jp/about/whitepaper/2026/pdf/) から全体版（または章ごと）のPDFをダウンロードし、`data/pdf/` に置く
3. **Claude の APIキーを用意する**：Claude Console（Anthropic の開発者向け管理画面）でキーを発行する。Claude.ai の有料プランとは別契約で、使った分だけの従量課金
4. `.env.example` を `.env` という名前でコピーし、`ANTHROPIC_API_KEY=` にキーを書く

## 使い方

```bash
python build_index.py                          # 索引を作る（白書1冊で数十秒）
python ask.py "地熱発電の導入が進まない理由は？"   # コマンドラインで質問
python ask.py "..." --dry-run                  # 検索結果だけ見る（APIキー不要）
streamlit run app.py                           # Web画面で質問
```

回答の例（形式）:

```
（結論を1〜2文、必要なら箇条書き）[1][2]

出典:
  [1] whitepaper2026.pdf 123ページ（第2部 > 第3章 ...）
      「引用された文…」
```

### ベクトル検索を加える（任意）

言い換えた質問（「増えない理由」⇔「導入が進まない要因」）への強さが上がります。

| 設定 | 必要なもの | 特徴 |
|---|---|---|
| `RAG_EMBEDDER=local` | `pip install sentence-transformers`（初回にモデルを自動ダウンロード） | 無料、手元のPCで動く |
| `RAG_EMBEDDER=voyage` | `pip install voyageai`、`VOYAGE_API_KEY` | Anthropic が推奨する埋め込み。多言語の検索品質が高い |

設定を変えたら `python build_index.py` で索引を作り直してください。

## 精度の評価

```bash
python eval/evaluate.py eval/questions.csv                 # 検索の精度（APIキー不要）
python eval/evaluate.py eval/questions.csv --with-answer   # 回答と引用まで（APIを使う）
```

`eval/questions.csv` に、質問・正解ページ・白書に答えがあるか（yes/no）を書きます。
正解ページは白書を見て記入してください（同梱の8問は記入前のひな形です）。30〜50問あると、設定の比較（キーワードのみ vs ベクトル併用、抜粋数など）に使える精度になります。

## テスト（APIキー不要）

```bash
python tests/test_pipeline.py
```

白書の体裁を真似た架空のテスト用PDF（`data/pdf_test/`）と、Claude の応答形式を真似た偽の応答で、取り込みから引用の表示までを確認します。

## 既知の制約

- 図表の中の数値（グラフの画像）は文字として取り出せないため、検索対象になりません。図表のタイトルと本文中の説明は対象です
- 図表の中に文字として埋め込まれた項目名や注記は、近くの本文の抜粋に混ざることがあります
- 複雑な表は、行・列の並びが崩れて取り込まれることがあります
- `RAG_EMBEDDER=local` の経路は、開発環境ではモデルを取得できなかったため、実機での確認が必要です
